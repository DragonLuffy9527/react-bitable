| 项 | 事实 |

## 二、飞书 / WPS 的能力全景（分层）

两家的功能可以归到 7 层。分层比列清单更有用，因为**不同层的实现难度差 1~2 个数量级**。

### L1 视图层

| 能力 | 飞书 | WPS |
| --- | --- | --- |
| 表格视图 | ✅ | ✅ |
| 看板视图 | ✅ 拖拽卡片改状态、紧凑模式、附件当封面 | ✅ |
| 画册视图 | ✅ 紧凑模式、附件可视化 | ✅ |
| 日历视图 | ✅ 拖拽改日期 | ✅ |
| 甘特视图 | ✅ 真实时间轴、拖拽改期、里程碑、周/月/季/年维度 | ✅ 含任务依赖 |
| 表单视图 | ✅ 可公开发布、写回数据表 | ✅ |
| 查询视图 | — | ✅（WPS 独有第 7 种） |
| 视图级配置 | 筛选/分组/排序/行高/冻结列，临时配置与保存分离 | 同 |
| 视图管理 | 新建/复制/删除/拖动排序/锁定/个人视图 | 同 + 视图级权限 |

### L2 字段层（飞书 28 种 ui_type）

- **常规**：多行文本、邮箱、条码、数字、单选、多选、日期、复选框、电话、超链接、附件
- **业务**：进度、货币、评分、人员、群组、单向关联、双向关联、地理位置
- **高级**：查找引用（Lookup）、公式（Formula）、流程（Stage）、按钮
- **系统**：创建时间、最后更新时间、创建人、修改人、自动编号

WPS 为「30 余种智能字段」，能力基本对齐。

### L3 数据处理层

筛选（含数字比较、日期区间、人员包含等全类型操作符）、多字段排序、多级分组、**分组汇总（计数/求和/平均/最大最小）**、条件染色、行内编辑、单元格区域选择与复制粘贴、键盘导航、撤销重做、批量填充、记录层级（父子）、行拖拽排序、列宽/行高/冻结、导入导出 CSV/XLSX、打印。

### L4 数据关系层（真正的分水岭）

- 一个 Base 内含**多张数据表**（上限 100 张，含仪表盘）
- 表间**单向 / 双向关联**
- **查找引用**（跨表按条件取数，底层是 FILTER）
- **汇总 / Rollup**（对关联记录求和、计数、去重计数）
- **公式字段**（100+ 函数、依赖图、循环引用检测）

### L5 协作层

多人实时协同（毫秒级同步）、单元格级编辑记录、评论与 @提及、通知提醒、分享链接与嵌入、历史版本与还原、回收站、移动端。

### L6 权限层

文件级（可管理/可编辑/可查看）→ 数据表级 → **行级**（按人员字段过滤）→ **列级**（字段可见/可编辑）→ **视图级**（WPS 2026Q1 新增）→ 自定义角色（飞书 30 个角色 / 200 协作者）。

### L7 平台层

仪表盘（飞书 15+ 组件：柱状/条形/折线/饼/面积/雷达/散点/组合/漏斗/词云/指标卡/排行榜/NPS/进度/透视表/切片器）、自动化流程（触发器 + 动作 + 连接器）、开放 API、AI 字段捷径与自然语言建表、模板库、应用模式。

## 四、覆盖率结论（两个口径）

| 口径 | 覆盖率 | 说明 |
| --- | --- | --- |
| **A. 单表前端体验**（一个表格该有的编辑体验） | **约 85%**（P0 → 75%，P1 → 85%） | 筛选/排序/分组/染色/编辑/撤销/填充/冻结/汇总/复制/导出/虚拟滚动，「手感」类能力已基本齐平飞书单表 |
| **B. 多维表平台**（飞书 / WPS 的完整产品面） | **约 18~22%** | 关系层、协作层、权限层、平台层几乎为空 |

差距的本质不是「少做了几个功能」，而是**产品定位差一个量级**：

- 当前是 **table engine**（一份数据、六种渲染）
- 飞书/WPS 是 **lightweight database platform**（多表 + 关系 + 计算 + 协作 + 权限 + 自动化）

## 五、难度分层：哪些是界面活，哪些是引擎活

这是最关键的判断。同样叫「加个功能」，成本可能差 100 倍。

### 第一类：界面活（★★ 以内，堆时间就能出）

看板拖拽改状态、日历拖拽改日期、表单写回、分组汇总、更多展示型字段、导入导出、虚拟滚动、打印、字段级搜索。

> 特征：数据模型不变，只补交互和渲染。**这一类占飞书功能表的一半以上，但只占价值的两成。**

### 第二类：引擎活（★★★~★★★★，需要重新设计数据层）

| 项目 | 为什么难 |
| --- | --- |
| 多表容器 | `useBitable` 单表 hook 要拆成多表 store，视图/字段/数据三层作用域重划 |
| 关联 + 查找引用 + 汇总 | 关系存储、引用完整性、级联更新、删除时的悬空引用处理 |
| 公式字段 | 表达式解析（AST）+ 依赖图 + 增量重算 + 循环引用检测 + 100+ 函数库 + 类型系统 |
| 仪表盘 | 图表本身不难（ECharts 半天接完），难在「维度/度量/聚合/联动/切片器」的配置模型 |
| 权限 | 行列级过滤要在**数据出口**做，前端只能做 UI 壳，必须有服务端 |

### 第三类：平台活（★★★★★，不是前端项目）

实时协同、自动化流程、AI 能力、组织架构对接、开放 API。

> 这一类的共同点：**需要服务端、需要运维、需要生态**。纯前端仓库无论怎么写都到不了。

## 六、建议路线

### P0 先补「六种视图都能用」（1~2 周，性价比最高）—— ✅ 2026-10-29 完成

1. ~~看板拖拽改状态（★）~~ → 已实现，并补了空泳道（否则拖不进没有记录的状态）
2. ~~日历拖拽改日期（★★）~~ → 已实现，保留原时间部分，跨月格可投放
3. ~~表单提交写回 `addRow`（★★）~~ → 已实现，按字段类型转换值
4. ~~甘特改成真时间轴：开始/结束日期字段 + 拖拽改期（★★★）~~ → 已实现，月/日双行表头、拖色条整体改期、拖右边缘改结束日

> 理由：这 4 项完成后，「六种视图」才名副其实。原先这是最大的**宣传与事实落差**。
> 遗留：甘特仍缺里程碑与任务依赖线，画册仍缺内联编辑——都是 ★★ 级增量，不阻塞。

### P1 补「表格该有的手感」（2~3 周）—— ✅ 2026-10-29 完成

1. ~~分组汇总~~ → 组尾汇总行（求和/平均/最大/最小/计数），按列配置；非叶子分组汇总全部后代记录；未分组时可出底部合计
2. ~~数字/日期操作符~~ → 新增 大于/大于等于/小于/小于等于/介于；求值抽成 `filtering.ts` 纯函数，数字剥千分位与货币符号、日期兼容斜杠格式、空值不参与比较
3. ~~单元格区域选择与复制~~ → 点选 + Shift 框选，Ctrl/Cmd+C 复制为 TSV（可直接粘进 Excel），非安全上下文降级 `execCommand`；**Ctrl/Cmd+V 粘贴**按列类型转换、越界裁剪、锁定列跳过，整次粘贴一步撤销
4. ~~方向键导航~~ → 方向键逐格移动、Shift 扩展选区、Esc 取消；编辑输入框时不抢键
5. ~~导出~~ → `exportView('xlsx' | 'csv')`，导出筛选/排序后的可见列；xlsx 自拼最小 OOXML（ZIP 存储模式），不引 SheetJS
6. ~~虚拟滚动~~ → 只渲染可视区 ±12 行，行高量化触发重渲染；**分组状态同样支持**（标题/数据行/汇总行摊平成一条坐标系跨组窗口化）

> 理由：这些是用户每天用 50 次的东西，比仪表盘重要。
> 遗留：虚拟滚动开启时跨屏拖拽填充需目标行在可视区内（DOM 里没渲染的行拖不到）；分组标题高度按 30px 估算，靠 overscan 吸收误差。

### P2 做「数据层重构」（1~2 月，分水岭）

1. `useBitable` → `BitableStore`（多表）
2. 表间关联（单向优先）
3. 查找引用 + 汇总
4. ~~数据源适配层（REST / Supabase）~~ → **已做行级部分**：`dataSource` 接口 + 写后同步（快照差分、300ms 防抖、失败保留待重试）+ `createRestDataSource` / `createMemoryDataSource`。列配置与视图仍在本机，冲突解决与实时推送未做

> 这一步做完，才配叫「多维表」；不做，永远是「表格组件」。

### P3 公式引擎（1~3 月，谨慎启动）

建议**不要自研完整表达式引擎**。可选路径：
- 用现成解析器（如 `expr-eval` / `mathjs` / `jsep` + 自写求值）做子集
- 只支持 `SUM/AVERAGE/IF/CONCAT/DATE` 等 30 个高频函数
- 明确不支持跨表引用，降低依赖图复杂度

### P4 平台层（不建议做）

仪表盘可以外包给 ECharts；权限、协同、自动化、AI 建议**明确不做**，改成「留扩展点 + 文档说明如何接后端」。

## 七、给项目定位的两条建议

**建议 1：把 README 的措辞收紧。**
现在是「类飞书多维表格的 React 组件库」，容易被理解成「飞书替代品」。建议改成：
> 一个零后端的多维表格**渲染与编辑引擎**：6 种视图、12 种字段、筛选/分组/染色/撤销/填充开箱即用，数据层可替换。

**建议 2：把「可替换的数据层」做成第一卖点。**
飞书和 WPS 都是封闭 SaaS，而你这个项目的真实优势是**受控组件 + 纯函数工具 + 零 runtime 依赖**，能塞进任何已有系统。与其追平台功能，不如把「接入成本」做到极致（数据源适配器、字段 schema 校验、SSR、主题、图标自托管）。

> 追功能永远追不上飞书；做「能嵌进别人系统的最小多维表引擎」，这个生态位是空的。
